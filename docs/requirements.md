## 1. 目的と対象範囲

指定時刻にTeams会議へ自動参加し、会議チャットへの挨拶、人数監視、自動退出、終了予定前の音通知を行う。

| 項目 | 確定した範囲 |
|---|---|
| OS・アプリ | Windows 11のTeamsデスクトップアプリケーションのみ |
| アカウント・言語 | 職場・学校アカウント1つ、日本語表示 |
| 実行前提 | PC起動済み、Windowsログイン済み、ロック解除済み、Teamsサインイン済み |
| 予定管理 | 利用者がツール内のカレンダーに登録する。日本時間固定 |
| 対象外 | ブラウザー版、個人用アカウント、自動アカウント切り替え、認証の自動化、ロック解除・スリープからの復帰の自動化 |

予定表の自動取り込みは要件に含めない。Teams内の既存予定への参加も、利用者がツール側に対象会議を登録する。

## 2. 予約と参加方法

### FR-01 予約管理

- 月表示カレンダーと選択日の予約一覧・編集画面で、予約を登録・表示・編集・削除できる。
- 会議名、開始日時、終了予定日時、参加方式、方式別の参加情報を必須とする。開始日時を自動参加時刻とし、終了予定日時を音通知の基準に使用する。
- 終了予定日時は開始日時より後とする。前の会議の終了から次の会議の開始まで10分以上空くことを、登録・変更時に検証する。条件を満たさない予約は保存しない。
- 単発と毎週の繰り返しに対応する。毎週の予約には繰り返し終了日を必須とする。
- 繰り返し予約の編集・削除は「今回のみ」「シリーズ全体」を選べる。繰り返し分も予定間隔の検証対象とする。
- 実行中の予約は編集・削除できない。シリーズ全体の操作でも実行中の回は変更しない。

### FR-02 参加方法の選択

予約ごとに次の3択から選ぶ。

| 方式 | 参加情報 | 指定時刻の操作 |
|---|---|---|
| ID・パスワード | 会議IDとパスワード | TeamsのID・パスワードによる参加操作を行う |
| リンク | 会議リンク | 対象会議をTeamsデスクトップアプリで開き、参加する |
| 参加ボタン | 会議名と開始日時 | Teams内のカレンダーで会議名と開始日時が一致する予定を探し、その予定の参加ボタンを操作する |

参加ボタン方式では、一致する予定が0件または複数件なら参加せず通知する。誤った予定を推測して選ばない。

### FR-03 入室と待機

- マイク・カメラを両方オフにして参加する。オフを確認できなければ参加せず通知する。
- ロビーなどで入室待ちとなった場合は全体で最大10分待ち、入室できなければ中止して通知する。再試行によって待機期限を延長しない。
- 認証はユーザー、入室承認は主催者が行う。
- 会議に入室したことを確認してから、入室挨拶・人数監視を開始する。

## 3. 挨拶

### FR-04 会議チャットへの自動送信

| タイミング | 文面 | 動作 |
|---|---|---|
| 入室完了後 | よろしくお願いします | 1回送信する |
| 自動退出直前 | ありがとうございました | 1回送信する |

- 送信先は参加中の対象会議のチャットとする。
- 送信結果が不明な場合は、重複防止のため再送せず記録する。
- 退出挨拶の送信確認を最大10秒待ち、確認できなくても退出する。
- 手動退出・強制切断など、ツールが退出前の処理を実行できない場合の挨拶は保証しない。手動退出後はその回の管理を終了し、退出挨拶を後から送らない。
- 入室・退出操作の再試行によって、挨拶を重複送信しない。

## 4. 人数による自動退出

### FR-05 人数の定義

- `N`：現在の、自分以外の参加人数。
- `M`：自分の入室後に観測した、自分以外の参加人数の最大値。
- 有効に取得できた人数を用い、10秒ごとに確認する。
- `M = 0` の間は退出判定をしない。人数取得失敗を0人として扱わない。

### FR-06 退出条件と優先順位

通常条件・待機省略条件とも厳密な未満とし、しきい値と同じ人数ではその条件を満たさない。

| 優先順位 | 条件 | 動作 |
|---|---|---|
| 1：待機省略 | `M >= 1` かつ `10 × N < M`（残り人数が最大人数の1/10未満） | 次の有効な人数確認時に、30秒の待機を省いて退出手続きへ進む |
| 2：通常 | `M >= 1` かつ `4 × N < M`（残り人数が最大人数の1/4未満）が30秒継続 | 退出手続きへ進む |
| 3：継続 | いずれにも該当しない | 会議参加を継続する |

- 退出手続きにはFR-04の退出挨拶と、会議からの退出を含む。「待機省略」は30秒の人数確認待機を省くことであり、挨拶を省く意味ではない。
- 通常条件を満たさなくなった場合、または人数取得に失敗した場合は、30秒の継続時間をリセットする。
- 両条件に該当しても退出手続きは1回のみ実行する。
- 予定の終了時刻や滞在時間だけを理由に強制退出しない。

### 境界値の例

| 最大人数M | 現在人数N | 判定 |
|---|---|---|
| 20 | 5 | 1/4ちょうどのため退出しない |
| 20 | 4 | 30秒継続で退出 |
| 20 | 2 | 1/10ちょうど。通常条件として30秒継続で退出 |
| 20 | 1 | 1/10未満。次の人数確認で待機を省いて退出手続きへ進む |
| 1〜3 | 0 | 1/10未満。次の人数確認で待機を省いて退出手続きへ進む |
| 0 | 0 | 判定しない |

## 5. 通知と会議の重複

### FR-07 終了予定前の音通知

- 現在の会議の終了予定時刻の10分前・5分前に、対象会議に参加中の場合のみ、ユーザーへ各1回音で通知する。
- 次の会議の開始時刻を基準にした通知ではない。
- 音通知によって自動退出は行わない。
- 既に退出済みなら通知しない。短時間の会議や遅れて入室した場合も、入室前に過ぎた通知を後から鳴らさない。
- 音量はWindows設定に従う。同一の通知を繰り返し鳴らさない。

### FR-08 次の会議との競合

- 次の会議の5分前にも現在の会議が継続している場合のみ、ユーザーへ音付きで1回通知する。
- 5分前を過ぎてから競合が判明した場合は、判明時に1回通知する。同じ予約の同じ競合を繰り返し通知しない。
- 通知の前後を通じて、人数による自動退出は継続する。
- 重複を理由に現在の会議から強制退出したり、次の会議へ自動で切り替えたりしない。
- 通知後でも、次の予約時刻までに現在の会議を退出できれば、次の会議へ予定どおり自動参加する。
- 次の予約時刻になっても会議中であれば、その予約はスキップする。後から自動参加しない。正常稼働時の10秒の処理許容遅延は、この競合判定を先延ばしする猶予にはしない。
- 利用者の予定間隔は10分以上のため、通常運用ではFR-07の通知時刻と重複しない。

## 6. 障害と復旧

### FR-09 失敗時の処理

| 状況 | 確定した動作 |
|---|---|
| 予約時刻を過ぎてツールを起動 | 過ぎた予約へ自動参加せず通知する |
| 一時的な入室操作失敗 | 30秒間隔で最大2回再試行（初回を含め最大3回）し、その後は通知して中止する |
| 認証要求・入室拒否 | 再試行せず、通知して中止する |
| ロビーなどで未入室 | 全体で最大10分で中止して通知する。再試行で延長しない |
| 会議中の接続切断 | 通知し、自動運転を停止する。ツールから自動再参加しない |
| 人数取得失敗 | 退出しない。通常退出の継続時間をリセットする。60秒連続で失敗したら1回通知し、退出せず再取得を継続する |
| 挨拶の送信結果不明 | 再送せず記録する |
| マイク・カメラのオフを確認できない | 参加せず通知する |
| ボタン方式で対象会議を一意に特定できない | 参加せず通知する |
| 退出操作失敗 | まだ退出していないと確認できる場合のみ最大2回再試行する。状態を確認できない場合、または再試行しても失敗する場合は通知して自動操作を停止する |

再試行は一時的な操作失敗を対象とする。マイク・カメラの設定確認不能や対象会議の特定不能では再試行しない。再試行で既に送信した挨拶を再送しない。

### FR-11 中断と復旧

- 予約を保存し、アプリ再起動後も読み出せる。
- アプリ再起動・ロック・スリープ・会議中の切断後は自動運転を停止状態とし、進行中の会議の制御を自動で引き継がない。
- 自動運転を再開するには利用者の明示操作を必要とする。再開時に過去の予約を実行しない。
- ロック・スリープ中の会議操作・通知は動作保証の対象外とし、復帰時も自動運転を停止したままにする。

## 7. 画面・操作・保存

### FR-10 操作画面

- 日本語のWindowsデスクトップGUIとし、通常利用でコマンド入力を必要としない。
- 月表示カレンダー、選択日の予約一覧・編集画面、次回予約、動作状態を表示する。
- ツールは手動起動する。起動時は一時停止状態とし、利用者が自動運転を開始する。
- 全体の一時停止・再開を操作できる。一時停止は自動参加・挨拶・人数による退出を止め、通知は継続する。
- 再開時に過去の予約を実行しない。
- Windows通知とアプリ内の実行履歴を提供する。

### FR-12 手動操作との関係

- 自動監視・挨拶・退出の管理対象は、ツール自身が参加した会議のみとする。
- 手動参加した会議は自動監視・挨拶・退出の対象外だが、次の自動参加との競合として扱う。
- 手動退出した場合、その回の管理を終了し、自動再参加や退出挨拶の後送を行わない。

### NFR-01 UI操作と表示条件

- UI Automationを用い、固定の画面座標に依存しない操作を行う。
- Teamsのウィンドウ移動、リサイズ、最大化、他ウィンドウによる被覆に対応する。
- 最小化されたTeamsを必要に応じて復元し、前面表示してよい。
- 保証対象は解像度1280×720以上、表示倍率100〜200%、複数モニターとする。
- これらは要求範囲であり、現在のTeamsでの実現性が検証済みという意味ではない。実装時に実機検証する。

### NFR-02 保存とログ

- 予約は同じWindowsユーザーのPC内に保存する。
- 会議パスワードはOSの保護機能で暗号化する。
- ログの保存期間は30日とする。
- パスワード、参加リンク、会議チャット本文をログに記録しない。
- 実行結果や失敗を、アプリ内の履歴から確認できる。

### NFR-03 時刻精度

- 正常稼働中は、指定時刻から10秒以内に参加操作・通知を開始する。
- 処理遅延が10秒を超えた予約はスキップして通知する。起動・再開前に過ぎた予約は、この10秒以内であっても後追い実行しない。
- 入室完了時刻はロビーや通信状況に依存するため保証対象外とする。
- 30秒間隔の入室再試行は、期限内に開始した同じ参加処理の継続として扱い、新たな遅延予約の実行とは区別する。

### NFR-04 配布

- EXEを含むフォルダーを配布し、利用者が起動できる形にする。
- 初版にはインストーラー、自動更新、Windows起動時の自動起動を含めない。

## 8. 受入条件

以下を実装後の受入確認に使用する。本書の完成時点では、これらの試験を実施済みという意味ではない。

| ID | 対象 | 合格条件 |
|---|---|---|
| AC-01 | 予約・参加 | 単発・毎週の予約を登録・編集・削除でき、3方式それぞれで対象会議へ参加できる |
| AC-02 | 会議特定 | 会議名と日時で一意に特定できない場合、誤参加せず通知する |
| AC-03 | 入室設定 | 入室時にマイク・カメラがオフであり、確認不能なら参加しない |
| AC-04 | ロビー | ロビー対象会議では承認時のみ入室後処理へ進み、10分未入室なら中止・通知する。再試行しても待機期限が延長されない |
| AC-05 | 挨拶 | 対象会議に指定文面を各1回送信する。送信結果不明でも重複送信せず、退出時の送信待ちは最大10秒 |
| AC-06 | 人数境界 | 第4章の境界値の例をすべて満たす。1/4ちょうどは退出せず、1/10ちょうどは待機を省かない |
| AC-07 | 監視 | 人数を10秒ごとに確認し、通常条件の30秒継続、条件不成立・取得失敗時のリセットを確認できる |
| AC-08 | 終了前通知 | 現在の会議の終了予定10分前・5分前に音通知し、通知だけでは退出しない |
| AC-09 | 重複 | 次の会議5分前に参加継続中の場合のみ通知し、人数判定は継続する。予約時刻の参加状況で次回の参加・スキップを分岐する |
| AC-10 | 障害 | 起動遅れ、入室失敗、接続切断、人数取得失敗で第6章の動作を満たす |
| AC-11 | 表示条件 | 保証する解像度・倍率・複数モニター構成で、ウィンドウ移動・リサイズ・被覆・最小化復元を含め3方式の参加・チャット・人数取得・退出を確認する |
| AC-12 | 保存 | 再起動後も予約を読み出せる。パスワードが平文保存されず、ログに禁止項目が含まれず、保存期間を超えたログが削除される |
| AC-13 | 予約検証 | 終了日時未入力・開始以前の終了・予定間隔10分未満・繰り返し終了日未入力では保存できない。間隔10分ちょうどは保存でき、繰り返し分にも適用される |
| AC-14 | 繰り返し編集 | 「今回のみ」の変更・削除が他の回へ影響せず、「シリーズ全体」が対象の回へ反映される。実行中の回は変更・削除されない |
| AC-15 | 起動・一時停止 | 起動時は自動操作せず、開始操作後に動作する。一時停止で参加・挨拶・自動退出が止まり、通知は継続する。再開時に過去予約を実行しない |
| AC-16 | 手動操作 | 手動参加した会議に挨拶・人数による退出を行わず、競合は検知する。手動退出後に挨拶の後送や再参加をしない |
| AC-17 | 中断復旧 | アプリ再起動・ロック・スリープ・切断後、自動運転が停止状態となり、進行中の会議を自動で引き継がない |
| AC-18 | 時刻精度 | 正常稼働時は指定時刻から10秒以内に参加操作・通知を開始する。10秒超の予約はスキップし、過去予約の後追い実行や競合判定の先延ばしをしない |
| AC-19 | 通知例外 | 終了前通知は参加中のみ各1回。退出済み・入室前に過ぎた通知は鳴らさず、後から判明した競合は1回通知する。音量はWindows設定に従う |
| AC-20 | 障害継続 | 人数取得の連続失敗60秒で1回通知し、誤退出せず取得を続ける。退出失敗は未退出確認時のみ最大2回再試行し、確認不能・失敗継続で停止・通知する |
| AC-21 | 再試行分類 | 一時的な入室失敗は初回を含め最大3回。認証要求・拒否・設定確認不能・対象不明では再試行しない。参加・退出の再試行で挨拶が重複しない |
| AC-22 | UI・配布 | 配布フォルダー内のEXEから日本語GUIを起動でき、コマンド入力なしで予約管理・開始・一時停止・再開・履歴確認ができる |

## 9. 実装前に検証する技術事項

- TeamsのUI Automationから、対象予定・参加ボタン・会議チャット・人数・退出ボタンを識別・操作できるか。
- 人数表示が自分を含むかを実機で確認し、自分以外の人数へ正しく換算できるか。
- UI上の人数が取得できない状態を、実人数0と区別できるか。
- リンク参加でTeamsデスクトップアプリへ誘導し、ブラウザー内での参加を必要としないか。
- チャットの送信完了、入室完了、退出完了を確認できるか。
- 実機検証時のTeams・Windowsのバージョン、画面構成、倍率を記録する。

要件定義時点では未検証。実現できない項目が見つかった場合、要件を満たした扱いにせず、代替案と影響を提示する。
