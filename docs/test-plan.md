# Teams 自動入退室ツール テスト要綱

- 版：1.0
- 作成日：2026-09-28
- 根拠：[要件定義書](requirements.md) の AC-01〜AC-22
- 実施結果：[テスト結果](test-results-2026-09-28.md)

## 1. 目的と判定

予約、保存、人数による退出、通知、配布 EXE の起動を確認する。Teams への実参加、チャット、退出、画面条件は、専用のテスト会議と参加者を用意した Windows 11 実機で確認する。

各ケースを「合格」「不合格」「未実施」で記録する。「合格」は期待結果を観測できた場合だけとする。自動テストや起動確認が成功しても、Teams との実連携を含む AC を全体合格とは扱わない。AC-01〜AC-22 のすべてを実機で確認し、不合格が0件になった時点で受入完了とする。

## 2. 環境と準備

- 自動テスト：Windows 11、Python 3.14、`requirements.txt` の依存関係、同じ Windows ユーザーで利用できる DPAPI。
- 配布テスト：`release\TeamsAutoJoin\TeamsAutoJoin.exe` と `_internal` を含むフォルダー一式。利用者の実データを使わず、隔離した `%LOCALAPPDATA%` で GUI を起動する。
- 実機テスト：日本語表示の Teams デスクトップ版、サインイン済みの職場・学校アカウント、会議 ID・パスコード、参加リンク、Teams 予定表上のテスト会議。主催者と人数変更用の協力者を確保する。
- 実機テストでは Teams・Windows のバージョン、表示解像度、倍率、モニター数、日時、実施者を結果に記録する。チャット本文や会議パスワードは証跡に記録しない。
- 自動運転は初期状態で一時停止であることを確認してから、専用のテスト会議に限り開始する。実会議や第三者の会議を試験対象にしない。

## 5. 記録と不具合対応

各ケースについて実施日時、環境、入力条件、実際の結果、判定、証跡の保存先を残す。失敗時は再現手順と期待結果との差を記録する。実会議への誤参加、マイク・カメラがオンのまま参加、誤退出、挨拶の重複送信があれば、関連ケースを不合格とし、修正後に再試験する。
